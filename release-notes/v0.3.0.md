# 0.3.0: preserve symbolic GANI placements

## Breaking changes

GaniPlacement.sprite_id: u32 is replaced by reference: GaniPlacementReference. Numeric references use Sprite(id); the observed uppercase PARAM1 token uses Param1. The enum implements Display for serializers. Literal constructors and field readers must migrate explicitly.

The parser no longer aliases the observed PARAM1 placement to sprite zero. seihai-draw skips this unresolved reference; no native slot resolution is implemented. Only the observed uppercase slot-one spelling is added. No native units, scheduling, other slots or case acceptance are established.

Known downstream migration includes servertools lat-core gani serialization and numeric assertions, plus Seihai mae tile rendering and default-asset assertions. Existing pins remain unaffected. Consumer bumps require the owner-approved published release and explicit source migration; they must not turn Param1 back into zero.

The primary corpus lead reviewed the source change against sanitized Classic+1.13/Era+1.0 structural observations. Independent authored parser and pixel-control tests distinguish numeric zero and symbolic placement. No original resources are included. See documentation/gani-placement-references.md for evidence limits.
