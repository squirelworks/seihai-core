The first 0.1 release: the version numbers now follow a written rule, and the tool-only modules are out of the public docs.

## Versioning

- From here on a breaking change to the public API bumps the minor version (0.1 to 0.2) and anything else bumps the patch (0.1.0 to 0.1.1). The README has the rule and what counts as breaking.
- `CHANGELOG.md` lists every release in one line each.

## API

- `dev`, `difftest` and `viewer` are `#[doc(hidden)]`. They stay public, so nothing that uses them breaks, but they are tools for the suite's own binaries and can change in a patch release.
- Nothing else changes from 0.0.30.

## Known gaps

- GS1 lowered to GS2 still refuses writes to player flags and the four player built-ins, and flag reads inside `with` (#30, #6).
- 7.x GS2 VMs and opcode 54 / `waitfor`'s timeout are open (#29).

## Consumers

Move every suite repo to `v0.1.0` in one round so each lock file holds one seihai-core.
