# 0.7.1

## NewWorld betas: COLORS is 8 bytes both ways

0.7.0 had the NewWorld betas (`NewWorldB1`, `NewWorldB2`) sending COLORS (13) as 7 bytes and reading 8. A Wine lab run of both betas against seihai-gserver on 2026-11-19 saw them send **8** on every login. Read as 7, the 8th byte lands in front of STATUS, so every login prop after it (STATUS, UDPPORT, ADDITFLAGS) is misread. With 8, every login prop parses.

`Props::colors_sent` is now 8 for both betas; `colors_read` stays 8. The 7 in the 2026-10-30 notes was most likely a misread. In that run the server sent only 5 colour bytes; the beta read 8 anyway and echoed those 8 back, and that echo still looks valid when read as 7.

Seihai's own `Connection::send_looks` now pads COLORS to 8 for these rows.

## Compatibility

No API changes. Only a profile value changes: a consumer that cuts or pads COLORS by `colors_sent` and `colors_read` picks up the fix by repinning.
