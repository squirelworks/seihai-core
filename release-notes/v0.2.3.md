seihai-core can now write binary levels and Graal MNG animations. Binary levels: `GR-V1.03` (`.graal`) and `Z3-V1.04` (`.zelda`), the inverse of its binary reader. seihai-servertools uses it for `level convert` to `.graal` and `.zelda`, the job of the classic TextConvert and nw-converter tools in reverse, for 1.x clients and old worlds.

## Changes

- `assets::encode_binary(level, BinaryLevel::Graal | BinaryLevel::Zelda)` returns the bytes and a list of what the format could not hold: layers above 0, NPCs and chests in `Z3-V1`, tile ids over 2047 in `Z3-V1` (kept as their low 11 bits), positions outside 0 to 223 (0 to 127 for baddies), baddy types that are not numbers, and `playerx+N` offsets in `Z3-V1` (written as `-1`).
- `assets::encode_board(tiles, bits)`: the board as run-length codes after the 2.05 editor's rule (a single run for 2 to 64 equal tiles, a double run for `A B A B`).
- `assets::encode_sign_text(text)`: sign text in the packed sign alphabet, the inverse of `decode_sign_text` (glyph tags and `#K(n)` escapes included).

- `assets::write_mng(frames, repeat)` writes an MNG shaped like Graal's own `gif2mng` (MHDR at 1000 ticks a second, mode 4 then mode 2 `FRAM`s, `TERM`), 8-bit palette frames with one transparent index; `read_mng` reads them back with the client's timing. `assets::write_indexed_png(frame)` is the one-frame case. `IndexedFrame` describes a frame. For seihai-servertools' gif2mng.

Tests round-trip a level with every section through the reader in both formats, and MNGs and PNGs through `read_mng` and the PNG reader.

No breaking API changes.
