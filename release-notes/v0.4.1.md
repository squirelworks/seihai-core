# 0.4.1

Corrects the public native GS1 command-ID lookup for client **2.05 rev 2**.
The previous 33-entry placeholder returned wrong IDs and omitted most of
the documented 161-entry table. For example, `name_for_opcode(600)` now
returns `Some("say")` instead of `Some("message")`, and
`opcode_for_name("show")` returns `Some(759)` instead of `Some(631)`.
`opcode_for_name("warp")` now returns `None` instead of `Some(606)`;
that name is absent from this build's native table.

The complete ordered lookup covers 600 through 760 in both directions.
Public signatures, direction constants and the 13 no-executor command
names are unchanged. These IDs describe a native parse-tree command table,
not GS2 bytecode or Seihai interpreter instructions. This correction does
not change parsing, execution, flag transport, or other builds' mappings.

Cleaned ID/name facts are attributed to **Graal_analysis by squirelworks**,
[pinned research](https://github.com/squirelworks/Graal_analysis/blob/07f55908c1eb888d7f44c41fcf18213b2d955113/npc-library/gs1-reference-205.md),
under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
The table and regression fixture omit source argument columns and prose;
no original binary bytes, addresses or decompiled implementation are included.

Regression tests check all 161 public lookup pairs against a pinned fixture,
explicit anchors, out-of-range IDs and absent names.
