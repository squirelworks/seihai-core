More of the GS1 to GS2 lowering (#6), from four new fixtures compiled with gs2-parser (`members`, `nested`, `tiles`, `elemlist` in `tests/fixtures/gs2/`).

## Changes

- **`players[i].x`, `.y`, `.dir` and the same on `npcs[i]`** (reads) lower to the element and then the member, as `members.gs2bc` encodes them. About 1,350 uses in the level scripts we hold. Writes to them, other fields after an index, and these reads inside a GS1 `with` stay errors.
- **GS2 member reads on an array element** (`players[0].x` in GS2 source) no longer put `OP_CONV_TO_OBJECT` between `OP_ARRAY` and the member: the GS2 front end now matches `members.gs2bc` byte for byte.
- **`tiles[x, y]`** read and written lowers to `OP_ARRAY_MULTIDIM` / `OP_ARRAY_MULTIDIM_ASSIGN` on `tiles` (`tiles.gs2bc`); `updateboard` already lowered. `board[..]` stays an error: GS2 has no `board`.
- **Lists inside a list literal** lower when no element anywhere calls a function or `random` (`nested.gs2bc`); with calls they stay errors.
- **A list stored into an array element** (`a[0] = {1, 2}`, and `setcharprop` into an element) lowers (`elemlist.gs2bc`).

No API changes.
