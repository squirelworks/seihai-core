# 0.7.0

This release was cut early so that seihai-gserver can serve the NewWorld betas. The rest of the old 0.7.0 roadmap (#108) moves to 0.8.0 (#123).

## The NewWorld betas have profiles

NewWorld beta 1 and beta 2 (`G2N15041`) are now client versions: `ClientVersion::NewWorldB1` and `NewWorldB2`. The rows come from Graal_analysis `client-internals/newworld-betas.md` and the `vnwb1`/`vnwb2` profiles.

- **Side builds.** Beta 1 is built on 2.05, and beta 2 on 2.1 (its binary is a 2.1 test 3 build). A new `Delta::side` marks a step whose delta does not carry into the next step, so 2.1 still follows 2.05. `previous`, `changes` and the generated tables compare a step with the nearest step before it that is not a side build.
- **What the betas change.** The built-in sword, bow, baddies, chests, horses and freeze are gone:
  - server ids 2, 4, 17, 18, 154 and 155;
  - client ids 7, 8, 11, 15, 16, 17 and 20.

  GANI (10) is a string, and default images are `.png`. Beta 2 has 165 GS1 commands and 2.1 test 3's file packets (no modtime).
- **COLORS width.** The betas send COLORS (13) as 7 bytes and read it as 8; every other build uses 5 and 5.
  - `Props` gains `colors_sent` and `colors_read`.
  - New `parse_player_props_sized` reads a prop stream at a given width.
  - `SessionState` reads server props at its build's width, and `Connection::send_looks` pads COLORS to the width its build sends.
- `G2N15041` leaves `NOT_SERVED`. The betas leave the offline-only list. `Era::for_version` gives beta 1 2.05's GS1 table and beta 2 the 2.1 table.
- **Still unknown.** The real betas ask the listserver for `newworld`, but these rows send `newmain`. What COLORS bytes 6 to 8 mean is not known.

## Every catalogued version token is accounted for

`KNOWN_TOKENS` gains the 25 tokens it lacked from the Graal_analysis catalogue:
- the RemoteControl and NPC Control logins;
- the NPC-server labels;
- the game tokens known only from server tables;
- the Worlds connector constants.

New `STAND_INS`, `NOT_SERVED` and `serve_as()`. Every game token now has one of: a profile, a nearest profile that a server serves it as, or a written reason it is not served. A unit test fails when a new token is not placed. `documentation/version-tokens.tsv` gains a `served_as` column.

## GS2 texts that are not numbers read as -1

This matches the real 4.20r8, 5.24r4 and 6.03r7 clients (lab, 94 cases). A text reads as its leading number when that number is non-zero. Only these texts read as zero:
- `"0"`;
- a hex zero;
- `""`;
- `"false"`;
- `"0.0"`, on 6.03r7 only.

Every other text reads as -1, and `"true"` reads as 1. The rule applies to arithmetic, `!`, comparisons, list search, in-range, timeouts and `maxlooplimit`. GS1 keeps its own rule (0). (#120)

## Secure list fetch for builds without a listserver

A secure list fetch for a 4.x to 6.x build uses 2.22's gen-5 list login (the oldest with a secure form) instead of failing. New `net::list_login_version` (squirelworks/seihai#564).

## Breaking changes

- `ClientVersion` gains `NewWorldB1` and `NewWorldB2`.
- `Props` gains `colors_sent` and `colors_read`; `Delta` gains `colors` and `side`.
- `offline_builds` loses the two NewWorld rows and `Family::NewWorld`.
- `TokenKind` gains `NpcControl` and `NpcServer`; `TokenGrade` gains `ScriptConstant`.
