The GS2 executor follows the VM of the client it presents as, from 3.153 to 6.03r7.

## Breaking changes

- **`exec::Outcome` has a new variant**, `WaitFor { object, event, timeout }`. An exhaustive `match` on `Outcome` needs an arm for it.
- **`strings::client_int` adds 0.0001 before rounding down**, as every client VM does, so `int(0.99995)` is now 1.
- **Numbers written as text in GS2** (`@` joins, `format("%f")`, `format("%s")`) use the client's writer: up to 9 decimals, cut rather than rounded, trailing zeros dropped.
- **Two numbers compare equal within 0.0001** in GS2 `==`, `<` and the rest, as in every client VM.

## Scripting

- `gs2::vm::VmProfile`: the rules of each VM read (3.153, 4.20r6, 4.20r8, 5.00r7, 6.01r1/6.03r7): which opcodes it handles, the stack and loop limits, `%`, `^` and shifts. `VmProfile::for_version` maps every `ClientVersion` to the read VM that is closest and not later; the Mac 5.12 build keeps PowerPC shifts.
- `Machine::for_version` and `Machine::with_profile` run a script by those rules; `Machine::new` keeps 3.153's.
- New opcodes run: 45/46/47 (local slots), 66/67 (`&&`/`||` as values), 104 (compare to -1/0/1, 4.20r6 on), 121 (add or join, 5.00r7 on), 49 (number list, 5.00r7), 48 (object literal, 5.00r7; gives null) and 11 (`waitfor`, 4.20r8 on, with `Machine::resume_waitfor`).
- `this.maxlooplimit` reads and sets the loop limit from 5.00r7, clamped to 100–1000000.
- An opcode the chosen VM has no handler for is skipped and logged.
- `documentation/gs2-vm-versions.md` records what was read in each client and what is still unknown.
