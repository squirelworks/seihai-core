seihai-core can now read and write GraalShop's movie mode. A `GANI0002` gani is a timeline of actors (characters, sprites, sounds and text) set by keyframes, where sprite mode has fixed steps. seihai-servertools builds its movie-mode editor on this (servertools #78).

## Changes

- `assets::gani_movie::GaniMovie::parse(text)` reads `FRAMES n` and the `MOVIE` … `MOVIEEND` block: `ACTOR <CHAR|SPRITE|SOUND|TEXT> <name>` … `ACTOREND` with `FRAME <n> key=value,…` keyframes. Pieces are split on `,` and trimmed, empty pieces are dropped, and a bare key deletes that key. It returns `Ok(None)` for a gani with no movie. `SINGLEDIRECTION` together with a movie, an unknown actor kind, and an unclosed block are errors.
- `Actor::state_at(t)`: for each key, the last value at or before frame `t`. `dx` and `dy` move in a straight line to the next keyframe that sets them.
- `Actor::set(frame, key, Some(v) | None)` edits like GraalShop's keyframe box. A keyframe left with no keys is removed.
- `GaniMovie::write_block()` and `frames_line()` write the block back in GraalShop's layout. `frame_at(step, looped)` wraps or holds the timeline.
- `truthy(value)` reads a boolean spelled `1`, `true`, `yes` or `on`.

The sprite table and the other header lines of a `GANI0002` file are still read by `Gani::parse`. Values are kept exactly as written. How GraalShop spells booleans and indexed keys, and the unit of `dx` / `dy`, are not known yet, because no saved `GANI0002` file has turned up.

Re-exported from `assets`: `GaniMovie`, `Actor`, `ActorKind` and `Keyframe`. No breaking API changes.
