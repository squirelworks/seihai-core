# 0.6.0

## Breaking changes

- `client::Login` has a new field, `secure: Option<net::SecureLogin>`. Callers
  that build `Login` by literal add `secure: None` to keep the old login, or
  pass a `SecureLogin` (squirelworks/seihai#564).

## The secure login in the client session (squirelworks/seihai#564)

`client::run` and `run_with` logged every game server in with the build's
own clear login, so a 5.x/6.x client built on them (Issho) sent the password
in clear inside the zlib frame even when the user asked for the Seihai secure
login. With `Login::secure` set, every game server of the session, the
5.x/6.x Login lobby and the server it warps to, is opened through
`net::login_gserver_secure` (`SEI00001`), as mae already does. A new test
(`tests/client_secure_login.rs`) checks that 6.03r7, 5.12 and 2.22 sessions
send the `SEI00001` hello and never the password, and that a session
without it logs in as before.

The secure **list** login still takes only the gen-5 list shapes (2.22,
2.31, 3.04). 5.x and 6.x have no listserver profile of their own and borrow
2.05's, so a caller fetches their list as 2.22. The error now says so
instead of "needs a 2.22 or later profile", which read wrong for 6.x.
