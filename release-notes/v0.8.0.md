# 0.8.0

The 0.8.0 milestone (#123): the Torque 3D side of every 3D build in the version profiles, the `seihai3d/1` extension contract, a GS2 compiler that matches the official server's output, and the 5.x/6.x script cache. Every other Seihai repo pins this tag for its next release.

## Breaking changes

- **`VersionProfile` and `chain::Delta` gain `three_d`**, the build's Torque 3D side (`protocol::three_d`). `Fields` is now 64 bits wide and `ThreeD` has new fields (`ground_cover`, `terrain_textures`, `drops_unknown_ghost`, `greyscale_rgba32_only`, `requires_sky`, `sky_gif`, `drawn`, `mirrors_2d_position`, `sees_2d_players`, `takes_2d_chat`; 41 fields).
- **`compile::Options` gains `no_var_cache` and `lambda_id`.** Callers that build `Options` without `..Options::default()` must add them. GS2 compiler output now follows the official server-side compiler, so callers that compared bytes with gs2-parser output will see different bytes.
- **`SessionState` gains script-cache fields** (`script_requests`), for the 5.x/6.x script cache (squirelworks/seihai#497).
- **`PlayerView` gains `guild`** (GS1 `playeringuild`, #63, #129).
- **`EffectHost` gains `mouse`** (GS2 `mousex`, `mousey`, #136).

## Graal 3D

- Every version profile has `three_d`: Torque protocol, game string, class table and framing, mission phases and control objects, `.ter` vs streamed terrain, terrain texture format, TorqueScript, DTS/DIF/3DS/MD3 versions, texture naming, the download filter and BigData limit. 3.04 to 5.12 (Windows and Mac) have one; each row lists the fields that are assumed rather than read, and helpers (`offers_terrain_chunks`, `runs_torque_script`, `requests_download`, `reads_dts`, `texture_request_name`, `accepts_control`, `sky_texture_request_name`, `needs_2d_position_relay`) gate behaviour per build. Mirrored from Graal_analysis `version-profiles/three-d.toml`.
- `three_d::THREE_D_420_LINUX` and `three_d::by_token` for Linux 4.20r6 and 4.20r8, which link as protocol 24 and have no version profile.
- New `protocol::three_d_ext`: the `seihai3d/1` extension handshake. This release defines the wire contract only; a real 4.20r8 or 5.x never sees it, and no capability is implemented yet.

## GS2

- The compiler follows the official server-side compiler: per-function variable cache, `OP_PARAMS`, `OP_TYPE_NULL`, smallest jump operands, jump threading, constant folding and more. Of 151 official captures, legacy mode matches all 151 byte for byte given each capture's lambda number. `no_var_cache` leaves out the cache for clients before 6.x.
- The executor keeps function values (`function () { … }`, `this.f`), calls through them, and reads caller-frame arguments correctly. `a[i]++` changes the element itself; `f()[1]` and `f().size()` work. GS1-to-GS2: `#v(..)` inside `#t(..)` or `#e(..)` compiles as its expression.
- `mousex` and `mousey` read the last click from `EffectHost::mouse`.

## Protocol and profiles

- The 5.x and 6.x script cache: `PLO_NPCWEAPONSCRIPT` (140) with the cache flag, `PLO_LOADSCRIPT` (197), and the new `scriptcache` module.
- New `protocol::version_pick`: reads a server's `Allowed:` list from its version refusal and picks the version to log in with.
- GS1 scripts lowered to GS2 get a wrapper only for the events they test, as a real 2.22 runs them (#130). This reverses the every-event wrappers from 0.2.17.
- The 5.12, 5.24r4 and 5.31r4 lobby login line is read from captures (#121, #133). NewWorld beta 1 and beta 2 stay one token (#128).
- The 2.1 row's `download_maps` now cites Graal_analysis #719's static read (ver9 on) instead of being inferred from 2.17.1.

## Hardening

- GANI frame drawing, clipped rectangle outlines and text rendering widen coordinates before clipping, so extreme origins no longer overflow.
- Own-player position updates apply precise X2/Y2 coordinates when the receiver profile accepts them.
- New own-VM acceptance tests for GS1 indexed loops and `with(player)`, numeric and text enums, and computed member access.

## Compatibility

Consumers move their pin from `v0.7.2` to `v0.8.0` in their own release PRs. The breaking changes above are additive fields; code that builds the changed structs with `..Default::default()` compiles unchanged.
