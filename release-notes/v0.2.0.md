For the 6.x client line (squirelworks/seihai#497 and #446): the GS2 scripts of the player's weapons, NPC scripts that come after their level or belong to a gmap neighbour, the player's props in GS2 scripts, and MIDI music.

## Changes

- **Weapon and class scripts (`PLO_NPCWEAPONSCRIPT`, 140).** `SessionState::weapon_bytecode` and `class_bytecode` keep the compiled GS2 by name, as sent; deleting a weapon (`PLO_NPCWEAPONDEL`) drops its script. `protocol::parse_script_delivery` reads the packet: a GSHORT header length `h`, the header (`type,name,cache flag,` and the cache key), and the body at `2 + h`, where the Linux 6.03r7 lab run found it (Graal_analysis `protocol/linux-603-network-gs2.md`). The client session hands them to the game in `OwnWeapons::bytecode`. `PLO_LOADSCRIPT` (197, the cache-hit form) is still not acted on: Seihai keeps no script cache.
- **NPC scripts the arrival did not carry.** `Live::npc_scripts` (`NpcScript`: level, NPC id, parsed script) gets each server NPC's `PLO_NPCBYTECODE` that was not in its level's `Arrival`: a script sent after the level settled (an NPC that came later, or a script sent again with other bytes), and the scripts of the gmap neighbours' NPCs, with their level, so the game can start them when it crosses into that cell. Each script goes once per connection.
- **`player.*` in GS2.** `EffectHost::player` (`PlayerSnap`: place, direction, chat, nick, account, hearts, counters) answers `player.x`, `player.chat` and the rest. Writing `player.chat` says it, as GS1's `setplayerprop #c` does; writing the place, direction, gralats, bombs or darts is the GS1 player variable (`Effect::SetPlayerVar`). `with (player) x = …` now moves the player rather than setting a script variable.
- **MIDI music.** `sound::render_midi` renders a Standard MIDI File (format 0 or 1; tempo changes, programs, volume and expression, pitch bend at note start, drums on channel 10) to mono 22050 Hz PCM with Seihai's own small synthesizer: the notes and timing are the file's, the timbre is not a General MIDI sound set. `decode_sound` takes `MThd` data, and `SoundEngine` plays `.mid` and `.midi` on the music slot, as `.mp3`.

## Breaking changes

- `client::OwnWeapons` has a new field, `bytecode`.
- `scripting::gs2::exec::EffectHost` has a new field, `player`.
- `SoundEngine::play` plays `.mid` music instead of returning `Outcome::NotAnEffect` with a "music skipped" note; that outcome is now only for unknown extensions.
