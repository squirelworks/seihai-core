# 0.5.1

## GS1 to GS2 lowering (#93)

`putbomb` and `shoot` were `Missing`: the 3.153 client's GS2 table does not
register them, so a GS1 script using them did not compile to GS2. Real
compiled GS2 weapon scripts call both by name on later clients (Graal_analysis
`npc-library/gs2-weapon-corpus-2026-11-14.md`): `shoot` in 25 weapons of a
2007 world written for 4.20r8/5.00r7 and in 67 of a 2018 world, `putbomb` in
5 of the 2018 world. They now lower as `Same`, keeping the GS1 argument
order. Together they were 260 of the failing units in the #93 corpus run.
This is inferred from shipped scripts, not from a lab run.

`putexplosion`, `putexplosion2`, `puthorse`, `putnpc` and `putnpc2` stay
`Missing`: neither the 3.153 table nor any real GS2 script has them. A lab
check on a real GS2 client is tracked in #104.

## 1.1.9 relay: the registration key (#63)

`relay::Client::set_registration_key` makes the client show a key to its
peers as relay type `8`, sent with the player's state when a peer joins,
as 15th Graal to 1.1.9 broadcast the key from `reg.code` (Graal_analysis
`formats/graalsav.md`, `protocol/relay-1998.md`). `duplicate_registration()`
turns true when a level-room peer shows the same key; the original then
says "Another player uses the same registration key like you. You will be
disconnected." The caller reads `reg.code` with `graaldes::code_read`. When
the key goes out, and that nothing is sent without one, is Seihai's
reading **[inf]**. New items only; nothing existing changes.

## GS2: an event's arguments are `params`

`Machine::call_event` also gives the event's arguments to the handler as
the local list `params`, so `params[0]` reads the first one, as scripts
written for the real clients do (`onKeyPressed`, `onActionClientSide`).
For that, `OP_CONV_TO_OBJECT` keeps an unqualified name that is one of the
function's own variables as that variable, so it can be indexed. Named
parameters work as before; a parameter called `params` takes its place.
