The shared client session (`client`, used by Ato and Issho) hands the view the player's own counters and the chat, says what the player types, and sends the sword swing and what the view builds for the server.

## Client session

- `Live::own` holds the player's counters as the server last set them with `PLO_PLAYERPROPS`: heart containers, power in half hearts, gralats, arrows, bombs, glove power, status and AP (`OwnStats`). A status display draws from it.
- `Live::chat` gets each chat line once as it comes in: bubbles said in the level, toalls, PMs and admin lines (`protocol::ChatLine`). The session state no longer keeps them.
- `Live::say` takes the lines the player typed. The network thread says each in the level with CURCHAT, so the server shows the bubble and runs chat commands such as `setnick`. Blank lines are dropped.
- `Other::chat` is the bubble over another player while it lasts. The loop now runs the bubble timers, so a bubble ends on the 2.05 rule after the speaker's empty CURCHAT.
- `Pose` gains `sprite` (the SPRITE value, `dir + 4 * S` during a swing on a sprite build) and `gani` (the animation a GANI build names, `sword` or `spin`). With a walk cadence both go into the cadence's props. Without one, a GANI build sends `PLAYERPROPS GANI` when the view's animation starts and ends (`gani_props_message`), and the walk message carries the sprite. `Pose` now derives `Default`.
- `Live::send` takes messages the view built for the server (a cut's `PLI_BOARDMODIFY`, bomb and arrow adds). The network thread sends them once the post-login frame has gone.

## Checks

- Unit tests in `client` cover the counters, the chat hand-over, the typed lines, the bubbles, and the swing on a GANI build (6.03r7) and a sprite build (3.153).
- No real client was run for this change; the Issho lab run (squirelworks/seihai#441) checks it end to end.
