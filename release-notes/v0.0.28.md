The client session can tell a client line about each game server before it logs in, and fetch files the client line names. Ato uses both for its Graal3D side.

## Client session

- `client::run_hooked` is `run_with` plus `Hooks`. `run_with` is unchanged and calls it with no hooks.
- `Hooks::on_server` is called on the network thread just before each login: the first server, then each `PLO_SERVERWARP` (178) target. `ServerJoin::is_graal3d` is true when the warp's name starts with `3 `, which is how the 4.20r6 and 5.x clients decide to open the Torque UDP link beside the TCP login.
- `Hooks::files` (`FileAsks`) takes names from the client line, asks the server for each with `WANTFILE` (or `UPDATEFILE` for a kept copy), and gives back one `FileAnswer` per name: the bytes, or `None` after `PLO_FILESENDFAILED`. A name asked for without an extension (the Sky's textures) is also answered by that file with one. Names still on the wire at a server warp are asked for again on the new server.
- `ServerWarp::is_graal3d` and `layouts::is_graal3d_name` test a name for the `3 ` prefix.

## Checks

- Unit tests in `client::hook_tests` cover the `3 ` names, extension-less matching, one answer per name, answers from kept copies and earlier failures, and asking again after a warp.
