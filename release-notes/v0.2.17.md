# GS1 dispatcher covers the era's events

A GS1 script that cannot be split into one function per event runs from
`__gs1run`. That dispatcher now has a wrapper for every event in the era's
closed list, so code outside the event tests runs when the host fires an
event the script never names. Events the script names stay first. A script
the per-event lift can still split does not gain those wrappers, and an
eventless script still runs at load.

`action…` names stay open ended: a wrapper exists only when the script
tests that name. Events the era does not have yet are not wrapped
(`playerdies` is absent before 2.01). `playerleaves`, `playerlogin` and
`playerlogout` are wrapped from the era the GS1 engine already accepts
them; that is the engine's list, not a claim that a client fires them.

The regression compares Seihai's GS1 engine with the lowered GS2 machine
on loopback. No original client was run. Direct GS2 calls and command
support are unchanged. No API changes.
