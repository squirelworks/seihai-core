Two GS1 lowering fixes from the first original-client run of Seihai's bytecode (#6).

## Changes

- **`setplayerprop` compiles to `player.*` assignments.** `setplayerprop #c,text` is now `player.chat = text`. `#n`, `#3`, `#8`, the colours and the attributes become `player.nick`, `player.headimg`, `player.bodyimg`, `player.colors[i]` and `player.attr[i]`. The real 6.03r7 has no `setplayerprop` function: it reported "Function setplayerprop not found" in the isolated lab of 2026-11-14. Other codes still compile to the call by name.
- **`playerscount` and `npcscount`** compile to `players.size()` and `npcs.size()`. Left as plain names, they read as 0 on 6.03r7, so the lab's follow script never ran.

## Lab: 6.03r7, 5.24r4 and 4.20r8

The lab ran in a Debian VM with loopback-only networking. A proxy put our bytecode into the client's NPC packet and logged its sha256. With these two fixes, all six kit scripts run on all three original clients, with no crashes and no script errors:

- the timer;
- `setimg` and touch chat;
- a text `showimg` with `client.` variables;
- `players[0]` follow;
- `tiles[]` + `updateboard`;
- the whole-script dispatcher.

The tiles script's tile 2047 is grass in the lab's pics1, so the effect only shows with a dark tile such as 632. That is a kit comment problem, not a compiler one. GServer-v2's own GS1→GS2 translator refused scripts 04 to 06. The sanitized results and payload hashes are in `documentation/lab/gs1-on-gs2-clients/lab-results.md`.

No API changes.
