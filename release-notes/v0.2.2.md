Whole-script GS1 lowering, `board[]`, `#I` and `#L`, a tool for running lowered scripts on original clients (#6), and three roadmap items (#7).

## Changes

- **Whole-script GS1 (the dispatcher).** A GS1 script the per-event lift cannot split now runs whole, as GS1 runs it: for each event the script names, `onEvent()` calls `__gs1run("event")`, and `__gs1run(__gs1event)` holds every statement outside the script's own functions in source order, with each event flag read as `__gs1event == "event"`. This covers code between event tests, events inside larger conditions, event tests with `else`, event flags read as values, and repeated blocks after one that can return. Scripts the lift splits keep their per-event functions. One difference is documented: GS1 runs a script for every event the NPC gets, the dispatcher for the events the script names.
- **`break` / `continue` outside a loop** end the run, as in GS1: a `return` in an event function or the dispatcher.
- **Message codes**: `#I(list,index)` on a `this.` / `client.` list is the element `list[index]`, and `#L` is `level.name` (Seihai's reading; part of the lab kit).
- **More element members**: `players[i].id`, `.hearts`, `.rupees`, `.bombs`, `.darts`, `.nick`, `.account` and `npcs[i].id`, `.width`, `.height`, `.image`, in the `members.gs2bc` encoding.
- **Corpus coverage**: of the 1,765 unique level scripts we hold that parse as 2.17, 1,201 now compile to GS2 (957 before this release). `tests/script_stress.rs` reports the count and keeps a floor of 1,200. Most of the rest use GS1 commands no GS2 client table has (`putexplosion`, `putcomp`, `hitcompu`), server-side commands, or flag names built at run time.
- **GS1 `board[i]` lowers** to GS2 `tiles[x, y]`. GS1 takes the index as `floor(i + 0.0001)`, so with `k = i + 0.0001` a read is `(k >= 0 && k < 4096) ? tiles[int(k) % 64, int(k / 64)] : 0`, and a write (plain or compound) is guarded by the same test. A written value that calls something is read into a temporary first, since GS1 works it out even off the board. An index that calls something is still an error ("put the index in a variable first"), because the index is read up to four times.
- **`examples/gs1c.rs`**: compiles GS1 files, prints the disassembly and what each client build is sent, and writes the `.gs2bc` and, with `--packet <npc id>`, the `PLO_RAWDATA` + `PLO_NPCBYTECODE` pair as GServer-v2 sends it. `documentation/lab/gs1-on-gs2-clients/` holds five scripts with on-screen effects for the original-client run.
- **Profile audit** (`protocol::audit`, `documentation/profile-audit.md` and `.tsv`): every profile row and every field the chain changes, traced to the step that set it, labelled read here, inferred here, carried, carried and flagged unknown, or carried with no binary. A test keeps the documents current.
- **Connection capabilities** (`protocol::connect`, `documentation/connection-capabilities.md`): `ClientVersion::native_connection` (direct game server, classic or gen-5 listserver, Login server) and `ClientVersion::discovery` (native, or borrowed from 2.05 by Seihai), plus `OfflineBuild::native_connection` (no network, relay lobby). A test checks that a borrowed list never counts as a native listserver.
- **Id 108**: a test pins which builds handle it, from the binary reads: 4.20r6, 4.20r8 and the Mac 5.12 do; 4.04r2, 5.00r7, the Windows 5.12, 5.24r4 and the 6.x builds do not (6.x still sends 162).

New public items only (`protocol::audit`, `protocol::connect`); no breaking changes.
