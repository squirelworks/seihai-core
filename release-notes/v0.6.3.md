# 0.6.3

## GS1 `keypressed` (2.17.1 and later)

`keypressed` is now a GS1 event from era V217 (2.17.1, 2.22, 2.31).
`ScriptWorld::key_pressed(code, key)` fires it on every object, with `#p(0)`
as the Windows virtual-key code, `#p(1)` as the lower-case character and
`#p(2)` empty. `SessionScripts::key_pressed` wraps it for clients. Older
eras run nothing and log nothing. The lab key sweep (2026-11-19) saw the
real 2.22 and 2.31 fire it with A as `65`/`a`/empty and S as `83`/`s`.

## GS1 to GS2: `keypressed` lowers to `onKeyPressed`

A GS1 `keypressed` event lowered to `onKeypressed`, but real 5.x and 6.x
scripts spell the handler `onKeyPressed`. The handler-name builder now
knows the words "key" and "pressed". Not yet checked on a real client:
whether 6.03r7 runs the handler. This release is what lets
seihai-gserver repin and run that lab check.

## Lab fuzz cases

Two new examples, `gs2_fuzzcases` and `gs1_fuzzcases`, write fuzz cases
for a real client in the lab. Each case comes with the value Seihai
predicts the client will report (see `fuzz/README.md`).

## Releases

The version now changes only in a release PR, which carries
`Release: vX.Y.Z` and is checked by `version-guard` (VERSIONING.md). When
a release PR merges and CI passes, the release workflow publishes the
release and its tag automatically.

## Compatibility

No breaking changes. `ScriptWorld::key_pressed` and
`SessionScripts::key_pressed` are new.
