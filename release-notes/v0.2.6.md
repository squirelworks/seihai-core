GS1 flag writes now reach the server from original clients (#30).

## Changes

- **GS1 `set`, `unset` and `setstring` on a plain flag** lower to an assignment to `client.gs1_<flag>` (`= true`, `= "value"`, `= ""` to clear). Real 5.24r4 and 4.20r8 clients have no GS2 `set()` and send only `client.` flags. seihai-gserver keeps such a flag as `<flag>` and sends it straight back, so `player.<flag>` reads it in the same session and after a relogin (`GS1_FLAG_PREFIX`). Other servers keep `client.gs1_<flag>`. A bare `set x;` is stored as `x=1`.
- Still refused: assigning to a flag's plain name (`gotkey = 2`), reading a flag inside `with`, and `set` on `local.`, `clientr.`, `server.` or `serverr.` names.
- Seihai's GS2 host sends a flag for a `client.` write the same way.

No breaking API changes.
