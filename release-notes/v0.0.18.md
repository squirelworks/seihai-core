The 6.00r4 client profile and its `resolveHost` script builtin.

## Breaking changes

- **`ClientVersion::V600R4`** is a new variant, so an exhaustive `match` on `ClientVersion` needs an arm for it.
- **`protocol::Scripts` has one more field**, `resolve_host`. A struct literal of `Scripts` needs it; the `Scripts::GS1` and `Scripts::UNKNOWN` constants set it to `false`.

## Protocol

- 6.00r4 (`G3D26090`, Windows): a version-chain step after 6.00r2, with the same token and the same 93 server ids. Its send set and long frame length are taken from 6.00r2. `documentation/version-chain.md` and `.tsv` are regenerated.

## Scripting

- `net::resolve_host(host)`: a DNS lookup that gives the first IPv4 address (else the first address) as text. A literal address comes back as it is.
- `EffectHost::resolve_host`: when it is set, GS2 `resolveHost(host)` returns that lookup, or `""` when the name does not resolve. It is off by default and is meant only for 6.00r4 (`VersionProfile::scripts.resolve_host`). The lookup blocks the calling thread.
