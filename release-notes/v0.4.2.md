# 0.4.2

Adds `protocol::graal2002::Graal210ReceiveBuild` and
`SessionState::set_graal210_receive_build` for explicit Windows 2.1 build
selection. Start with `SessionState::for_version(ClientVersion::V210)`,
then select `Public20011113` or `World(Graal2002Build::...)` from known
build metadata. Neither the login token nor FileVersion identifies these
builds. Existing callers and generic profiles are unchanged.
The override does not choose a matching login token or outgoing protocol;
in particular it is not a complete ver7/ver8/ver9 connection profile.

The override installs the complete statically observed receive bindings:
public 2001 has 66, ver7 has 55, ver8/ver9 have 56, ver10/ver13 have 60,
and v22 has 69. For example, ver10 ignores chest ID 4 while public and
v22 retain it, despite sharing `GNW31101`; only v22 binds 175–177 here.
Bindings are non-default dispatcher destinations, not native wire tests,
sender contracts or proof that unexamined payload layouts match.

Only the public 2001 selection changes the reader for 170/174 and 171/172.
A short flag packet preserves prior state; the first byte enables the flag
only above the wire bias 32. The map reader accepts two text fields;
coordinates default to zero unless four fields exist, then parse
independently with zero fallback. These are parsed map specifications,
not proof of native resource resolution, image loading or display updates.
The tested fallback does not establish complete numeric-parser compatibility.
The later four-field reader and middle-world-build layouts stay unchanged.
ID 173 already preserves the entire payload, including empty text.

This does not implement v22's active-level shot gate or local gmap preload,
ver10's gated Control-NPC installation, or any script execution. It does
not identify a genuine 5.12 build or infer whole-profile equivalence.
Other properties of the V210 base profile remain inferred.
