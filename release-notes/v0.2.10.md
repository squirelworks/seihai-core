seihai-core can now read and write the 1.x client's `.code` files and the classic clients' DES-hidden strings. A Graal 1.1 folder keeps its guild in `guildname.code` and its registration key in `reg.code`. The RemoteControl password and some list host names are hidden the same way.

## Changes

- New module `graaldes`.
- `GraalDes::new(key)`: DES-ECB as the clients run it. It is a d3des port that takes key bits LSB first, which is the same as standard DES with each key byte bit-reversed. It uses the RustCrypto `des` crate, a new dependency (MIT OR Apache-2.0).
- `block` and `block_text`: the 24-byte block, made of a length byte, up to 23 bytes of text, and padding.
- `string_encrypt` and `string_decrypt`: the 48-character form, where each byte is written as two nibbles plus `0x20`. `RC_PASSWORD_KEY` is the key for RemoteControl 1.33 to 1.41.
- `code_write` and `code_read`: the 48-byte Guildmaker `.code` file. The block is encrypted once under `AXBORG15` and once under `VERGRAAL`. On reading, the two halves must decrypt to the same block, and the length byte must be in range; otherwise the file is refused, as the client refuses it. Text over 23 bytes is cut, as Guildmaker cut it.

Tests:
- the classic DES test vector, through the key-reversal step;
- two `.code` halves and one 48-character string, matched against an independent implementation (Graal_analysis `tools/file-formats/graaldes.py`);
- a damaged file being refused.

The shipped sample `.code` files are third-party files, so they are not used.

No breaking API changes. Using it where Seihai opens a 1.x client folder is left to the client.
